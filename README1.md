# Отчёт по практической работе: CI/CD и автоматизация разработки

В данном отчёте представлены алгоритмы выполнения, использованные команды и результаты практических кейсов по настройке CI/CD пайплайнов.

---

## Кейс 1: Настройка простого пайплайна CI с использованием GitHub Actions

### Алгоритм выполнения:
1. Создание локальной структуры проекта и инициализация репозитория через `git init`.
2. Создание каталога конфигурации `.github/workflows/` и файла `ci.yml`.
3. Настройка базового сценария автоматической сборки при событии `push`.
4. Фиксация изменений и публикация репозитория на GitHub.  
![Запущенный процесс](/all-ci-cd-cases/images/1.1.PNG)
### Команды:
```bash
git init
mkdir -p .github/workflows
# Создание файла .github/workflows/ci.yml
git add .
git commit -m "Add GitHub Actions CI pipeline"
git branch -M main
git remote add origin <URL-репозитория>
git push -u origin main  
```
## Кейс 2: Автоматическое тестирование с использованием GitLab CI/CD

### 1. Описание проделанной работы (Алгоритм):
* В корневой директории общего репозитория `all-ci-cd-cases` создан конфигурационный файл `.gitlab-ci.yml`.  

![Структура](/all-ci-cd-cases/images/2.1.PNG)  

* В файле прописаны основные этапы работы пайплайна (stages): `build` (сборка проекта) и `test` (автоматическое тестирование).
* Определён базовый Docker-образ `node:18-alpine` для изолированного выполнения команд сборки и тестирования.

![Внутрянка](/all-ci-cd-cases/images/2.2.PNG)  
* Настроены задания (jobs) для вывода информации о завершении сборки и успешном прохождении модульных тестов.

![Результат](/all-ci-cd-cases/images/2.3.PNG)  


### 2. Использованные команды:
```bash
# Создание конфигурационного файла GitLab CI/CD в корне проекта
touch .gitlab-ci.yml

# Добавление файлов в индекс Git, фиксация и отправка в репозиторий
git add .gitlab-ci.yml README.md
git commit -m "Case 2: Add GitLab CI/CD pipeline configuration"
git push origin main  
```
## Кейс 5: Настройка непрерывной интеграции с использованием Jenkins

### 1. Описание проделанной работы (Алгоритм):
* В корневой директории репозитория создан декларативный файл сценария автоматизации **`Jenkinsfile`**.
* Описана структура пайплайна, состоящая из трёх последовательных этапов (stages): `Build` (сборка), `Test` (модульное тестирование) и `Deploy` (развертывание).
* Настроено использование агента `any` для выполнения задач на доступных исполнителях Jenkins-сервера.
* Прописаны логирующие шаги (`echo`) для имитации успешного прохождения каждого этапа сборки.

### 2. Использованные команды:
```bash
# Создание файла конфигурации Jenkinsfile в корне проекта
touch Jenkinsfile

# Добавление файла в систему контроля версий, коммит и отправка в удаленный репозиторий
git add Jenkinsfile README.md
git commit -m "Case 3: Add Jenkinsfile pipeline configuration"
git push origin main
